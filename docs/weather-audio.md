Signal uses browser speech to read current conditions and today's forecast as soon as weather becomes available. There is no recording preparation, voice catalog request, or speech request to the server. It uses the saved English browser reading voice and speaking speed, with the device voice as the automatic default. The existing weather location and Celsius units are unchanged.

There is no weather audio section in the dashboard. Open the seven-day forecast, then **Change location** to find **Read weather on opening**, **Read weather now**, and **Stop reading**. The automatic-reading setting remains saved on this device. Desktop browsers try immediately; phones requiring speech activation read on the first tap or keypress. A browser blocking the opening attempt retries on interaction. Manual reading starts directly in the button handler.

Weather reads once per opening. Refreshing weather or changing location stops the previous reading without repeating it automatically. Opening a headline player or article stops weather before the other player starts. Missing weather or unavailable browser speech leaves the dashboard silent. The full summary is split into short speech sections for mobile engines.

Validation: run `npm run iis:typecheck` and `npm run test:client`. Run `node tests/weather-audio.test-browser.mjs` with the host's Playwright module in `SIGNAL_PLAYWRIGHT_MODULE` and, when needed, `SIGNAL_BROWSER_CHANNEL=msedge` for browser speech lifecycle and dashboard integration checks.
