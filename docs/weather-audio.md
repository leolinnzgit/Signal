Signal uses Azure Speech to read current conditions and today's forecast when Azure narration is configured. It reuses the authenticated article MP3 streaming service, the saved English recorded reading voice (or the server's configured Azure default), and the saved speaking speed. Playback can start before synthesis finishes, and Azure credentials stay on the server. There is no separate weather voice catalog request. The existing weather location and Celsius units are unchanged.

There is no weather audio section in the dashboard. Open the seven-day forecast, then **Change location** to find **Read weather on opening**, **Read weather now**, and **Stop reading**. The automatic-reading setting remains saved on this device. Desktop browsers try immediately; phones requiring speech activation start on the first tap or keypress. If native autoplay is blocked, the next tap retries the same prepared URL directly in the gesture handler, without another synthesis request. Weather can play even on a device without browser speech.

Weather reads once per opening. Refreshing weather or changing location stops the previous reading without repeating it automatically. Opening a headline player or article stops weather before the other player starts. Stopping, disabling, or leaving weather cancels pending requests, status polling, and native playback. Completed streams use the existing session replay cache.

If Azure is unavailable before playback starts, weather falls back to the saved English browser voice and speed, with the device voice as the automatic default. The full summary is split into short speech sections for mobile engines. A blocked fallback retries on interaction. A failed Azure stream after playback starts stops with a retry message, so the forecast is not repeated over itself. Missing weather or unavailable audio leaves the dashboard silent.

Validation: run `npm run iis:typecheck` and `npm run test:client`. Run `node tests/weather-audio.test-browser.mjs` with the host's Playwright module in `SIGNAL_PLAYWRIGHT_MODULE` and, when needed, `SIGNAL_BROWSER_CHANNEL=msedge` for Azure playback, autoplay retry, cancellation, browser fallback, and dashboard integration checks.
